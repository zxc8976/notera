# 自動筆記駐守2 Constitution

## Core Principles

### I. MVP 優先與避免過度設計
專注於最小可行性產品 (MVP)。僅實作當前需求，嚴格遵循 YAGNI (You Aren't Gonna Need It) 原則。拒絕為了未來可能的需求而進行過早的最佳化或複雜設計。保持架構簡單，避免過度工程化。

### II. 可測試性驅動
所有功能必須具備可測試性 (Testable)。在編寫程式碼之前或同時，必須考慮如何驗證其正確性。單元測試與整合測試是交付的一部分，不可省略。無法測試的程式碼即為不可接受的程式碼。

### III. 高品質標準
程式碼必須清晰、易讀且易於維護。錯誤處理必須完善，避免靜默失敗。文件必須與程式碼同步更新，確保知識的準確傳遞。追求卓越，不接受粗製濫造的解決方案。

### IV. 多語言與在地化支持
系統輸出應遵循使用者選擇的介面語言（預設為正體中文）。針對課程內容，應保留原文（如日文術語、程式碼關鍵字）並提供對照或翻譯，確保學習內容的準確性與可追溯性。文件與開發溝通仍以正體中文為主，但產品輸出需具備多語言適應能力。

### V. 穩健性與防禦性程式設計
系統應對非預期輸入（如格式錯誤的 Markdown 或 HTML）具備韌性。啟發式演算法（Heuristics）必須採取保守策略，優先避免破壞現有內容（False Positives），而非追求極致的清理效果。對於破壞性變更，必須進行回歸測試。

## Governance

本憲章是專案的最高指導原則。任何程式碼變更或架構決策都必須符合上述原則。
修改本憲章需要經過團隊討論並進行版本升級。
所有 Pull Request (PR) 與 Code Review 都必須驗證是否符合本憲章的規範。
